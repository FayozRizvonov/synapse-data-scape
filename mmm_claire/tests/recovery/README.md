# Parameter recovery

## Why this exists

Every number the pipeline reports about the real dataset — r², contributions, ROI, VRR,
channel efficiency — is a claim about parameters that cannot be checked, because the true
parameters of a real market are not observable. "Did the model train properly?" has never
been answerable from the dovato data alone.

In-sample `fit_metrics` cannot answer it: r² measures reproduction of the periods fitted.
Holdout and backtesting cannot fully answer it either — they measure *prediction*, and a
model can forecast acceptably while attributing the effect to the wrong channels, which is
the failure mode that matters when the output is a budget recommendation.

Recovery answers it directly. Generate the target from known coefficients, fit the model,
and ask whether the posterior finds them again.

## How it is set up

`synthetic.py` generates the target using the model's **own** forward computation — the
same one `src/validation/holdout.py` mirrors in NumPy — at the model's own functional form:
geometric adstock, then Michaelis–Menten saturation, then a linear sum.

There is therefore **zero misspecification by construction**, and that is the point. A model
that cannot recover parameters from data generated by its own equations is not struggling
because reality is complicated. It is failing because the parameters are not identified at
this sample size, because a prior is overpowering the likelihood, or because a transform has
destroyed the signal before the likelihood ever sees it.

The truth respects every hard constraint the model imposes, so a miss is informative rather
than a foregone conclusion:

| constraint | enforced by |
|---|---|
| `beta_media > 0` | `softplus(beta_media_raw)` |
| `upper > mid > lower` | funnel hierarchy on the prior means |
| `gamma ∈ [0.3, 2.0]` | `clip(..., 0.3, gamma_cap)` |
| `theta ∈ [0.01, 0.5)` | `clip(theta_raw, 0.01, theta_cap)` |

`theta` and `gamma` are the cleanest targets in the set, because they sit inside the
nonlinearity and are scale-free — unlike the betas they need no affine correction, so a miss
on them cannot be blamed on bookkeeping.

### One manipulated variable

`--media-scale` changes how media is scaled before it reaches the model, and nothing else:

- **`raw`** — activity as counts. Exactly what the pipeline feeds the model today.
- **`mean`** — activity divided by its own mean, so each channel averages 1.0.

Comparing the two isolates the effect of media scaling on identifiability from every other
difference between runs.

### Why it bypasses the stability controller

The harness calls `build_pymc_model` + `sample_model` directly rather than
`run_stable_model`. The controller escalates draws and then **tightens priors** until its
diagnostics pass, and a tighter prior improves R-hat while making the posterior *less*
informative about the truth — so letting it run would confound the measurement. Level 0 is
what production uses on a clean first attempt, so that is what is measured, with R-hat / ESS
/ divergences reported so we can see whether production would have escalated.

## Running it

```bash
cd mmm_claire
/opt/homebrew/Caskroom/miniconda/base/envs/mmm_cl/bin/python tests/recovery/run_recovery.py --media-scale raw
/opt/homebrew/Caskroom/miniconda/base/envs/mmm_cl/bin/python tests/recovery/run_recovery.py --media-scale mean
```

Needs the `mmm_cl` conda env (PyMC 5.25), not `.venv`. Exits non-zero on `FAIL`, so it can
gate a change to `pymc_mmm.py`. The generated dataset, `truth.json` and
`recovery_result.json` are written to `tests/recovery/_run_<scale>_T<periods>/`.

Useful flags: `--periods` (33 matches the demo dataset), `--draws`, `--tune`, `--chains`,
`--seed`, `--out`.

## Reading the output

Three things decide the verdict, reported separately because they fail separately:

- **coverage** — share of parameters whose true value lands inside the posterior 90%
  interval. Nominal is 0.90, so a couple of misses across ~25 parameters is expected; a
  collapse to near zero is not.
- **bias(sd)** — `(posterior mean − truth) / posterior sd`. Around ±1 is noise. A parameter
  sitting several sd from truth with a *narrow* interval is the worst case: confidently wrong.
- **sampling** — max R-hat, min ESS, divergences. These say whether the sampler explored the
  posterior, which is a precondition for reading anything else.

Two columns separate the two reasons a parameter can be unrecoverable:

- **`signal`** — how much of the regressor's time variation survives saturation
  (`CV(x_sat) / CV(x_raw)`). Near zero means the likelihood is being shown a constant, and no
  amount of sampling can recover a coefficient on a constant.
- **`media share of fitted mu variance`** — how much of the fitted signal media actually
  carries. Near zero means media entered as a constant and was absorbed by the intercept,
  **whatever its coefficients say**. This is the number to check before believing any
  contribution or ROI output.

The run also reports the worst pairwise correlation among the saturated regressors. A
recovery failure caused by a collinear design matrix is our own fault, not the model's, so it
is audited rather than assumed.
